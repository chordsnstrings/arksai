# ArksAI — project memory

A self-hosted, Claude-Code-style web coding agent powered by DeepSeek, with an
engine-orchestration layer (Suno for music, more later). This file is the
durable context to reuse every session.

## Product vision (north star — read first)
ArksAI is for **general, non-technical people**, NOT developers. Promise: describe it once → get ONE finished thing that **looks perfect, works perfectly, and is actually live/usable** — zero user iteration ("Apple, not Windows"; the model/"brain" is swappable; quality comes from the SYSTEM). Two pillars, both built:
- **A. One-shot quality**: `taskProfile.ts` (classify the request → end-user deliverable type + isVisual + tier) drives an opinionated `designSystem.ts` (`designCore` + per-type packs, injected into the prompt for visual tasks only) + the bundled **UI kit** (`server/assets/ui-kit/` tokens+components+themes; `add_ui_kit` tool) + a **gating internal design-critique loop** (uiCheck `DESIGN_RUBLIC`/`parseDesignVerdict` → `runVerifyGate` REVISE→escalate→re-render, MAX 2 rounds, `config.designGate`) + a visual model floor. The agent iterates internally so the USER never does. Per-build: offer ONE quick curated style choice, then automatic.
- **B. Live deployment**: `publish_app` tool + TopBar Publish button → `deploy/publish.ts` snapshots the app to `data/deployments/<slug>/`, classifies static vs node/python, runs server apps via the durable `deploy/registry.ts` (survives sessions, `recoverDeployments` restarts on boot). Public, auth-free serving at **`/apps/<slug>/`** (`routes/deployments.ts`) — static files or reverse-proxy with HTML rewrite+`<base>`. `deployments` table; client `DeploymentsDialog`. v1 is path-based on the Droplet; subdomains/TLS/custom-domains + external hosts (DO App Platform) are the deferred next step.

## System audit (2026-06-15) — full report in `AUDIT.md` (on `main`)
A hands-on audit ran ALL 52 plays end-to-end (real API + Playwright/mupdf capture). Verdict: **core quality is high** — product UI, reports/decks, and web apps (microanimations + responsive + self-hosted Google-font typefaces) meet the bar; 13/14 apps published live. Ranked flaws to fix one-by-one (don't re-discover):
- **P0 agent/host isolation:** `AGENT_UNRESTRICTED=true` runs the agent shell as the SAME user IN the server process — a web-app build's `pkill node`/`npm install` **killed the server (×2)** and mutated the host repo. Fix = spawn agent children with a dedicated low-priv `uid/gid` (`exec.ts`/`processes.ts`/`registry.ts` + a `Dockerfile` user + chown `/data`) + an always-on `pkill/kill/fuser` denylist in `bash.ts`. (Testing mitigation = an auto-respawn server supervisor.)
- **P1 spreadsheet models aren't formula-driven — RESOLVED (2026-06-15).** Two-part fix landed. (1) The "no formula support" claim was STALE: commit `8c76445` already added formula+cached-result plumbing — `toCell`/`toRow` in `excel.ts` convert `"=B2*C2"` and `{f,v}` into ExcelJS `{formula,result}` cells, and it works (a real run produced 191 live cross-sheet formulas). (2) The REAL gap was **enforcement**: the model used formulas only ~1 in 6 times, and the gate couldn't catch a formula-less model — `checkDeliverable` only *counted* formulas and the vision review renders computed VALUES (so a `=SUM()` and a typed-in literal look identical). Fixed by `auditFormulaModel(wb)` in `deliverableCheck.ts` (pure; reads `cell.f` directly): a workbook with **0 formulas** that shows derived numbers (a Total/Net/Ending-Balance/Growth ROW carrying literals, or a multi-sheet model with an Assumptions/Drivers tab + ≥30 numeric cells) is flagged → seeded into `designDefects`/`designVerdict='revise'` BEFORE the vision early-returns (so it fires even with no MiniMax egress) → the existing 1-round bounded revise (`reviewDeliverables`→`runVerifyGate`/`runReportGate`) sends it back with a targeted "use live formulas" instruction. Plain data tables (no derived rows, no assumptions sheet) are never flagged — calibrated against all 6 sweep files + the test fixtures. Steering also tightened (excel.ts description + `FIN_SHEET` in `expertise.ts`: hard-coded totals "WILL BE REJECTED", prefer `{f,v}`).
- **P1 MiniMax design-gate fails silently** when vision errors (`uiCheck.ts`) → make it loud. **P2:** dup errored deployments on re-publish (no GC in `publish.ts`); faux-logo ⚠ icon on some report covers (`prompts.ts`); `.docx` uses Calibri not the editorial font (embedding needs TTF assets, `docx.ts`).
- Re-validate any fix by re-running the affected plays via the API harness (create session w/ `task`+`model` → send brief + an autonomous suffix → poll → screenshot via `/apps/<slug>/` or mupdf).

## Stack & layout
- **Projects** (persistent workspaces grouping sessions): `projects` + `project_files` tables, `sessions.project_id`. A project holds custom instructions, default repo/branch/mode/model, branding (accent/logo), and a knowledge base (files on the volume at `data/projects/<id>/knowledge/`, copied into each session's `knowledge/` at setup with doc-extraction). Sessions created in a project INHERIT its defaults; the runner injects a "## Project" block (instructions + knowledge index + branding) + `project:<id>` memory scope. API `routes/projects.ts`; client `ProjectDialog.tsx` + sidebar Projects→Sessions grouping. Deleting a project detaches (keeps) its sessions.
- npm workspaces: `server/` (Fastify + TS), `client/` (React + Vite), `shared/types.ts` (the contract).
- Storage: dual driver in `server/src/db` — PostgreSQL when `DATABASE_URL` is set, else SQLite on the volume. The store (`server/src/sessions/store.ts`) is async.
- Agent loop: `server/src/agent/runner.ts`. Tools in `server/src/agent/tools/`. Prompts in `server/src/agent/prompts.ts`.
- Engines/orchestration: `server/src/engines/` (registry + suno). Add an engine = registry entry + a gated tool.
- Modes: chat / plan / code / **report**. Report mode (`render_report` + `add_fonts` tools, report block in `prompts.ts`) turns pasted text/CSV/uploads into a designed PDF or 16:9 deck via bespoke HTML/CSS → headless-Chromium `page.pdf()`; curated toolset via `REPORT_TOOLS` in `tools/index.ts` (no git/verify). **No fixed templates** — each report is designed bespoke but MUST follow the protocol (minimal/modern/typography-first, light by default, charts+tables, centered cover, page-break-safe). `add_fonts` installs self-hosted Inter/Source Serif 4/Space Grotesk (`server/assets/report-fonts/`) so fonts are always embedded. Agent ALWAYS asks branding (colors/accent or upload a logo). Both doc+deck per request; narrative+cited benchmarks allowed, never fabricate figures.
- **Report PAGE MECHANICS (verified, baked into the prompt)**: margins go on `@page{margin:18mm 16mm}` so they repeat on EVERY physical page (NOT on a fixed-width padded container — that was the continuation-page bleed bug). Cover is centered with `min-height:calc(100vh - 36mm)` (36mm = 2× the vertical margin; `@page:first{margin:0}` is NOT honored by Chromium) AND `page-break-after:always` so it's isolated. Tables: compact (`padding:1.1mm 2.6mm`, 9pt, lh 1.3), centered, zebra rows + faint column hairlines, `<thead>` repeats. **Verify PDFs by rasterizing with the `mupdf` npm pkg** (WASM, no native deps) → PNG → Read it; headless Chromium can't screenshot a PDF (it downloads it).
- **Report quality lessons**: reports default to **MiniMax** when keyed (else Pro), NEVER Flash — Flash produced cover bleed, lonely pages, dark boxes, invisible text. Protocol mandates: content FLOW (no forced per-section breaks → lonely pages); CONTRAST safety (no text == bg/accent; callouts LIGHT); ICONS inlined (external `<use href>` doesn't render in Chromium PDF — `add_fonts` ships `icons.svg` as an inline-source). **Design quality (research-backed)**: RESTRAINED palette — ink/charcoal numbers, accent used only ~5–10% (don't colour every number); COMPOSITION — fill each page ~85–100%, balance whitespace, NO orphan KPI tiles (even grid), group a chart with its insight callout (wrap, break-inside:avoid), 2-col grid for dense text; CHARTS — flat 2D, no 3D/gradients/shadows/gridlines, direct value labels, muted base + accent on the key series only. **VISUAL QC via see_image/MiniMax-VL is MANDATORY** — critique every page like a design director and iterate (needs MiniMax egress; blocked in old sessions). Core needs no MiniMax; vision QC (`see_image`) lights up when keyed. **Editorial/newspaper upgrade (2026-06, from user feedback on the Hormuz report)**: (1) HEADING-BLEED was still happening (`break-after:avoid` alone is insufficient) → the protocol now mandates a MECHANICAL anti-orphan: wrap each section's heading + its opening paragraph (its "lede", kicker too) in `<div class="lede">` with `break-inside:avoid` so the pair always moves as ONE unit and a heading can never strand at the page bottom. (2) Side margins widened to **`@page{margin:20mm 26mm}`** (24–28mm guidance, cover calc 2×20mm) for generous newspaper gutters — text never edge-to-edge. (3) New EDITORIAL STRUCTURE toolkit (hairlines that separate focus points): kickers/eyebrows, ruled section headings, full-measure `.rule` section dividers, 2-col body with a `column-rule`, a running `.masthead`. ## Engine notes
- Engine roster lives in `server/src/engines/registry.ts` (`listEngines()`), surfaced at `GET /api/engines`. Each engine = registry entry (gated on its key) + a tool. Keys are read in `server/src/config.ts`.
- Suno (sunoapi.org/apibox): `generate_music` tool, gated on `SUNO_API_KEY`. Cost per track added to the session cost bar (`SUNO_COST_PER_TRACK`, default $0.08). The real API call was never validated from the sandbox (egress) — validate on the Droplet; adjust request shape in `server/src/engines/suno.ts` if it errors.
- MiniMax (`server/src/engines/minimax.ts`): the "anything DeepSeek can't do" provider. **`arksai-max` = MiniMax M3, NOT Anthropic** — MiniMax merely offers OpenAI- *and* Anthropic-*protocol*-compatible surfaces; the provider/model is MiniMax. Don't frame it as Anthropic. Gated tools (`tools/minimax.ts`): `see_image` (vision — also the verify-gate visual check), `generate_image`, `text_to_speech` (needs `MINIMAX_GROUP_ID`), `generate_video`. LLM is OpenAI-compatible (`minimaxBaseUrl=…/v1` + `minimaxModel`, default **`MiniMax-M3`**; **M3 is natively multimodal so vision runs on M3 too** — `minimaxVlModel` also defaults to M3; old `MiniMax-VL-01` is an INVALID id).
  - **BILLING IS BY KEY TYPE, not endpoint (the big gotcha):** a **Subscription Key (`sk-cp-…`)** draws on the Token Plan quota; a pay-as-you-go **`sk-api-…`** key bills the (often empty) credit wallet → `insufficient_balance (1008)` *even when the dashboard shows 100% plan quota*. Same error on BOTH `/v1` and `/anthropic` — it's the key, not the route. Check plan quota: `GET https://api.minimax.io/v1/token_plan/remains` (covers `general`+`video`).
  - **M3 MUST be called via the ANTHROPIC endpoint, not OpenAI (THE big 2026-06-15 finding, verified live).** On the OpenAI surface (`/v1/chat/completions`) M3's thinking is **forced ON and unbounded** — on a real agentic prompt it reasoned 20k+ chars and **never emitted a tool call in 150s** (then our `max_tokens` truncated it into a silent empty turn = the "spreadsheet hang"). Every OpenAI thinking-control knob (`reasoning_effort`, `thinking`, `enable_thinking`, `chat_template_kwargs`) is **IGNORED**; `reasoning_split:true` only relocates reasoning into `reasoning_content` (it does NOT bound it). On the **Anthropic surface (`https://api.minimax.io/anthropic/v1/messages`) M3 thinking is OFF by default** → it called `generate_spreadsheet` in **~2.8s**. So the runner now routes MiniMax through an Anthropic-format adapter (`createMinimaxStream` + `toAnthropicMessages`/`anthropicSseToOpenAI` in `runner.ts`) that translates our OpenAI-shaped loop to/from the Anthropic wire format; DeepSeek still uses OpenAI. Thinking is left **off** (fast, decisive tool use; `thinking:{type:'adaptive'}` = ON = the slow/hang path — MiniMax's docs recommend adaptive for agentic quality, but it's minutes/turn, so off is our default for now). **Gotchas:** (1) `fetch` has no timeout → the adapter idle-aborts at 120s (M3 buffers tool-arg generation server-side with ~30s silent gaps that are normal). (2) M3 **stalls under concurrency** on the Anthropic endpoint (concurrent streams hang) — keep concurrent M3 runs low. (3) Multi-turn with thinking ON requires echoing the model's `thinking` blocks back **unchanged** (incl. `signature`); we don't preserve them yet, so only enable adaptive after adding that. (4) Models on `/anthropic`: `MiniMax-M3` (1M ctx, multimodal) + `M2.7`/`M2.5`/`M2.1`(+`-highspeed`, ~100 tps) coding models — M2.x always think. Token plan healthy (sk-cp); M3 rate limit 200 RPM / 10M TPM.
  - Capability ids `image-01`/`speech-02-hd`/`MiniMax-Hailuo-02` are likely **stale** (current gens: Hailuo 2.3, Speech 2.6) — confirm before use; tune `minimax*Cost`. Music stays on Suno.
- Orchestrator model **ArksAI Auto** (`arksai-auto`) + **ArksAI Max** (`arksai-max` = MiniMax LLM, shown/selectable when keyed). Routing in `server/src/agent/router.ts` (pure heuristic: task text + mode → Flash/Pro/MiniMax tiers, escalates to a stronger model when verification fails, MiniMax→Pro fallback on hard error). ## Gotchas learned the hard way
- Empty JSON body → Fastify 400. The client must not send `Content-Type: application/json` without a body; server has a tolerant JSON parser. (Caused the DELETE-not-working bug.)
- Agent apps default to `PORT=4000` (childEnv) so they can't collide with / kill ArksAI on 3000.
- DeepSeek v4 models default to THINKING mode — for tiny calls (titles) use the non-thinking `deepseek-chat` alias or the token budget is eaten by reasoning.
- The sandbox/container has noise listening ports that are NOT apps (saw 2024, 2025, plus ephemeral 34xxx). Canvas must never auto-load the *lowest* port (`ports[0]`). `pickPreviewPort` in Canvas.tsx prefers known dev ports (agent default 4000 first, then 5173/3000/8080/…) and only auto-picks a single plausible 3000–9999 port otherwise; `orderPorts` lists recognised dev ports first. (This was the "canvas won't load apps" bug — it had been loading port 2024 and showing 502/401.)
