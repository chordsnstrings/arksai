# ArksAI — Feature List

A self-hosted, Claude-Code-style web coding agent for **non-technical teams**: describe
something once → get one finished thing that looks perfect, works perfectly, and is
actually live/usable. Powered by MiniMax (the LLM brain + image/vision/speech/video), with Suno for music.

> **Maintenance:** keep this file current — every shipped change that adds, removes, or
> meaningfully alters a feature should update this list in the same commit.
> _Last updated: 2026-06-19._

---

## Core product & agent
- Autonomous agent loop — streaming, tool-calling, stall guard, context truncation, graceful error handling.
- **Shareable per-chat links** — every session has its own URL (`/s/<id>`) reflected in the address bar (deep-link / bookmark / reload reopens it — including older chats past the first page, fetched on demand; back-forward works), plus a **🔗 Link** button in the top bar to copy it. A link to a deleted or inaccessible chat shows a clear "this chat isn't available" panel (the URL is kept so it can be retried) rather than silently dumping you on the home screen.
- One seamless chat — no modes to pick. The user just talks; ArksAI reads the request and moves itself into whatever it needs — chat, plan, build (code), report, or image generation — with the right curated toolset. Under the hood there are still 4 modes (Chat / Plan / Code / Report) + capability tools, but the user never toggles them (a read-only chip in the TopBar shows what it's doing). Power users can still force one with `/mode`.
- Tooling: file read/write/edit, glob/grep, bash + persistent background processes, git, web search/fetch.

## Orchestration & engines
- **One engine: MiniMax.** ArksAI runs entirely on MiniMax — the LLM brain (M3 + the fast M2.7-highspeed model) and all multimodal capabilities (vision, image, speech, video). No model menu for everyday use: the chat picks the model itself.
- **ArksAI Auto (the default)** — picks the concrete model per task: **M3** for quality/visual/agentic/report/legal work, the **fast model (Flash)** for quick/light turns; escalates Flash → M3 when verification needs more muscle. Server-authoritative cost in the footer. Power users can still force **ArksAI Max** (M3) or **ArksAI Flash** (M2.7-highspeed) via `/model` or the advanced New-session dialog.
- **ArksAI Max** — MiniMax M3. Called via M3's **Anthropic-compatible endpoint** (thinking off by default → fast, decisive tool use; the OpenAI surface forces unbounded thinking and stalls), through an adapter that keeps the rest of the agent loop unchanged. **Self-healing speed (never hangs):** M3 can over-buffer on complex turns, so if a turn exceeds a deadline the run auto-switches **within MiniMax to the fast model (Flash)** to finish — M3's refinement by default, a guaranteed finish when it's slow. The stall is detected by racing each stream read against the deadline (so a hung socket can't block the loop even if the abort doesn't propagate), with M3's reasoning stripped from the history on handoff so it always completes — closing a class of bug where a build could hang with no output. Large single-shot structured outputs (a full spreadsheet/deck/doc) get a shortened deadline so they hand off in ~30s instead of waiting the full window.
- **MiniMax capability tools:** `see_image` (vision), `generate_image`, `text_to_speech`, `generate_video` (Hailuo).
- **Suno** music engine — full toolkit, per-track cost: `generate_music` (AUTO mode from a description, or CUSTOM mode with a rich ~1000-char style field + structured lyrics; controls for vocal gender, style weight, weirdness, and negative tags to exclude styles), `generate_lyrics` (structured words only, no audio — free), `extend_music` (lengthen/continue a prior track), and `cover_audio` (AI-cover a source track in a new style). The agent is steered as a Suno expert (style = comma-separated components, vocal cues in parens, strongest line first) and confirms the brief before the first paid generation. Default model is config-driven (`SUNO_MODEL`).

## One-shot quality system
- Task classification (`taskProfile`) → deliverable type + isVisual + tier.
- Opinionated design system + a bundled UI kit (tokens/components/themes, `add_ui_kit`) injected for visual tasks; per-type design standards (web/app, report, docx, xlsx, pptx).
- **Universal visual-quality gate** (`deliverableCheck`) — EVERY deliverable is rendered to image(s) and design-reviewed by a senior-design-director rubric (M3 vision), then bounded-revised: web apps (live Chromium), PDF reports/decks (mupdf raster, per page), .xlsx/.docx (HTML render), and .pptx (LibreOffice or a faithful preview). The same "looks perfect, works perfectly" guarantee across all types, not just web apps. A **deterministic, model-free structural pre-check** (per-page ink coverage) catches lonely near-empty pages instantly — even when no vision model is available — so each revise round is cheap and targeted (reports now allow up to 2 quality-first revise rounds). The gate also covers the cases that used to slip: generated **images** are validity-checked (a 0-byte / truncated / error-page download is rejected, not shipped); an **app built in report mode** gets a real runtime boot + smoke-test (not just doc rendering); the **formula audit** flags a typed-in derived row (Total/Growth/Margin) even when the rest of the model uses formulas; and if the visual review ever can't run (vision/renderer unavailable), it **says so out loud** instead of silently passing.
- Per-type functional check ("it actually works"): xlsx re-open + no #REF/error cells **+ calculation models must be formula-driven** (a finance/cash-flow/budget/forecast sheet built with hard-coded totals/balances/growth is auto-flagged and sent back to add live `=SUM(...)`/cross-sheet formulas — the vision gate can't catch this since it renders computed values, so this reads the cells' formulas directly); docx re-open + embedded fonts; pptx valid slides; pdf page/blank/bleed; apps boot + routes + interaction.
- Vision runs on M3's Anthropic endpoint (thinking off → fast, decisive; bounded by a timeout so it degrades, never hangs).
- Visual model floor — non-trivial visual/report work never runs on the cheapest model.

## Bulletproof verification
- Static gate (typecheck/lint/test/build) + runtime gate (boots the app, exercises routes).
- Parameterized-route filling (`:id`/`{id}`/`<int:id>`/`:slug`) + an interaction pass (seeds inputs, submits a form, clicks primary buttons).
- Headless-Chromium UI smoke test (blank/console-error/failed-request detection).
- Post-publish smoke test of the real `/apps/<slug>/` URL — a broken deploy is caught and handed back to the agent, never the user.
- **Resilient app/preview proxy** — the reverse proxy that serves published apps (`/apps/<slug>/`) and the in-app preview reads the upstream response defensively and retries once on a dropped/stale connection, so a transient "premature close" can't surface as a 500 error page; an upstream that's genuinely down returns a clean "restart it" 502 instead.
- **Resilient model streaming** — if the connection to the model drops mid-reply (a "premature close" / terminated socket), the agent reconnects and redoes the turn (bounded), and a `turn_reset` event clears any partial output so the retry never shows doubled text. If M3 stalls, the run switches within MiniMax to the fast model to finish — so a slow or flaky turn still completes instead of dying with an error.
- **Self-contained apps (no CDN)** — built apps vendor their libraries (charting, etc.) locally and self-host fonts, with one real root `index.html`; nothing is pulled from an external CDN at runtime, so a published dashboard's charts can't silently break when a third-party CDN rate-limits/403s.

## Deliverables & deployment
- **Publish & share a 24-hour preview** (`publish_app` + the TopBar "Publish & share") — ship a site/app (static or node/python) to a **public URL anyone can open, no login** at `/apps/<slug>/`, served via a process registry that survives restarts (boot recovery). Every publish is a **24-hour preview**: a boot-started janitor auto-deletes it (process + files + record) 24h after publishing; re-publish to refresh. The dialog shows a live "expires in …" countdown. (Single-Droplet constraint for now — a permanent tier comes with a bigger server; pre-existing deployments without an expiry are left running.)
- Auto-export (zip download chip) + auto-canvas — the canvas auto-opens and loads the result (web app, PDF, spreadsheet, or doc). Generated **compliance machine files** (WPS `.sif`, PINT AE e-invoice `.xml`) are surfaced as downloads too, so a produced filing actually reaches the user.
- Styled office docs: `generate_spreadsheet` (exceljs, formula-driven, validated — and a built-in **formula recalculator** recomputes each formula's cached value before saving, so the in-app preview shows correct numbers instead of a model's stale/0 cached value; the formula is preserved so the download always recalculates in Excel) and `generate_doc` (docx) — documents embed the editorial typefaces (Source Serif 4 display + Inter body, the same as the reports/app), so they render designed everywhere instead of as office default. `generate_doc` also takes a **designed cover page** (masthead · accent title · one-line thesis · a **KPI band** of headline numbers · metadata footer) and `chart` blocks that embed **publication-grade `render_chart` images** — so a brief/report reads designed end-to-end, not as a wall of text.
- **`generate_pptx`** — real, editable PowerPoint (PptxGenJS): editorial 16:9 decks with a **designed cover** (masthead · accent title + thesis · a **KPI band** of headline numbers · metadata footer · `CONFIDENTIAL`) and a **dark/light slide rhythm** (per-slide theme), **publication-grade charts** via `render_chart` (dual-axis/heatmap/… embedded as crisp images, beyond the basic native bar/line/pie), title/section/bullets/two-col/stat/quote/table/image layouts, one accent, and an embedded preview for the canvas + the visual gate.
- Report mode — PDFs and 16:9 decks with a full editorial protocol (newspaper margins, anti-orphan `.lede`, kickers, rules, page mechanics); charts/figures are ATOMIC (`.keep`/`.fig`) so nothing splits across a page, and every page is auto design-reviewed before delivery. A **"get the first render right"** rule set targets the three defects the gate used to churn on — **lonely / half-empty pages** (forced per-section page-breaks are now forbidden; content FLOWS to fill ~85–100% of every page, a stray card grid sits with its narrative, never alone), **cornered/tiny charts** (every chart is a full-measure `.fig` on its own row and the SVG is auto-made **fluid** so it fills the column instead of collapsing with colliding axis labels), and the **white-frame background** (the page colour lives only on html/body or a `.bleed` page) — so the first render passes review fast instead of looping expensive revise rounds. **Token-efficient by design:** once the PDF/deck is rendered, the raw web-research dumps from earlier turns (web_search / web_fetch / fetch_data — already baked into the document) are auto-trimmed from context so the QC/revise turns don't re-pay for them, cutting a research report's token use dramatically. If a run ever does brush the per-run safety budget **after a good document was produced**, it now **completes normally and shows the file** (with a soft "this took a bit more processing" note) instead of erroring over a finished PDF. The protocol also hardens the anti-half-empty rule (NO interior page below ~70% full — a short profile/overview section merges with its neighbour) and enforces a single **output language** (English, or the user's language) so stray non-Latin characters never leak into the prose.
- **`render_chart`** — publication-grade charts as embeddable SVG (Vega-Lite → SVG, server-side, no browser/Python): line, multi-line, **dual-axis** (volume bars + a trend line), bar/bar-h, stacked, area, donut, and **heatmap** (e.g. month×year). Editorial defaults baked in — flat 2D, muted base + the report accent on the key series only, direct value labels, light gridlines — so charts are on-brand by default and inline straight into the report HTML. The returned SVG is **fluid** (full-measure `width:100%; height:auto`, viewBox kept) so it fills its `.fig` block instead of collapsing into a corner, and the intrinsic size auto-grows with the data (more rows → taller) so axis labels never collide; it also rasterizes to a transparent PNG so the SAME editorial charts embed into `.pptx` decks and `.docx` documents.
- **Two deterministic quality tools** — `validate_palette` checks a brand palette for **WCAG 2.2 AA contrast** (body text + links at 4.5:1, accent/large text/UI at 3:1) before any visual build and returns a corrected colour for any failing pair plus a ready-to-use token set (primary/accent/bg/surface/text/muted/line/link) so text is never shipped unreadable; `compute_financials` runs the **DCF (NPV + terminal value), the standard ratio set, budget variance (favourable/unfavourable), and a linear/growth forecast** so every derived number in a report or sheet is computed, not hand-typed. Both are pure, instant, no key needed, available in chat/code/report, and the relevant finance + design standards steer the agent to use them.
- **Designed, full-bleed cover** — the report cover is a **true edge-to-edge canvas** (a named zero-margin `@page` so the background field reaches all four paper edges — interior pages keep their margins), with a typography-led foreground: the **brand logo** in the masthead, accent title line, one-line thesis, a **KPI band** (even cell padding, breathing room), and a metadata footer. Dark / deep-accent / light field options.
- **Analysis & methodology rigor** — the report protocol now demands a systematic analysis pass first (profile columns, full cross-tabs, reconcile conflicting fields), an insight-led narrative (counter-intuitive reframe → evidence → ranked recs tied to specific data points), and a Methodology/Notes section (proxies + their limits, data gaps, source attribution).
- In-app doc viewer (xlsx/csv/docx/pptx → styled HTML); Canvas preview (Preview/Files/Doc tabs, port auto-detect).

## The flow (effortless AND expert)
- Smart intake — a short, type-aware brief (one round), then fully autonomous.
- Launchpad — input-first onboarding: a **personalized, time-aware greeting** opens it (by name — Claude-style "Coffee and ArksAI time, Kamran?", with varied lines per part of the day and an editable name that's **remembered server-side**, so it follows you across devices), the **chat box sits at the top**, and the team's example tasks are denser below — there to pick when you want them. The describe box accepts **file uploads, drag-and-drop, and clipboard paste** (staged, then attached to the new session before its first run), just like the main composer.
- Live "smart-work" progress bar — named phases with an anticipation creep so it never looks frozen; technical work stays visible (visible competence = trust).
- **Build you can watch (engagement-tuned)** — the moment you hit go the bar + footer appear (optimistic, zero gap); a live **play-by-play ticker** names the current action in human terms ("Looking at your image", "Setting the typography", "Designing the PDF", "Publishing it live") and auto-expands while working; switching chats never flashes; if a step needs retrying the studio says so kindly (plain language, never a scary error).
- **A real "it's ready" moment** — a successful build ends on a staged completion card with a **live thumbnail** of the finished app/document, one-tap **Open** and **Share** (✓ Live · Copied ✓), and a one-tap **"Fix & republish"** if a publish check fails — fires for every build, including static single-file sites. Publishing walks its real phases (Snapshotting → Installing → Booting → Checking the live URL) so the wait shows motion.
- **Pick up where you left off + calm dialogs** — the home screen shows a "Jump back in" row of your recent work; destructive actions use a styled in-app confirm (no jarring browser popup) and **Esc closes any dialog**; the live preview locks onto the exact port the build produced (no more wrong-port "Error").
- Self-healing reframed as confident "hardening it (pass N)" forward progress, not failure.
- Delivery moment — "Booting your live app…" loading + retry, and a completion card ("✓ Your app is ready" → Open / Get a shareable link) with a **"What's next?"** row of contextual follow-up chips (e.g. add a feature, tweak the design, turn a report into a deck) that pre-fill the message box so there's always an obvious next step.
- One-time "what's new" modal — shown once per user per version (remembered locally) right after sign-in, to keep people in the loop on recent updates.

## Smart agent
- Sees **every** upload, automatically — on each run the agent is told exactly what was just uploaded and how to open it (images → `see_image`, **available in every mode**; a logo → `extract_palette` for exact brand hex; office/data files → their auto-extracted `.extracted.txt` sidecar; anything else → `read_file`), so it acts without the user re-instructing. It never claims it "can't view" an image — vision is always on. Files attach via the `+` button, **drag-and-drop, or clipboard paste** (copy a file/screenshot → ⌘/Ctrl-V); a `📎` chip shows what's attached.
- **Brand from the logo** — `extract_palette` reads the real colours out of an uploaded logo (deterministic, no vision model needed) so the accent is taken from the brand; the **same identity (logo, accent, type) is applied across every deliverable** — web apps, decks, docs, and reports — and a deliberately beautiful palette is chosen when there's no logo.
- Auto mode/engine switching — `switch_mode` lets a chat become a build/report mid-conversation; the runner reloads the toolset, prompt, and engine on the fly with an inline note. It also routes **back**: a build/report session isn't sticky — if your next message is a different kind of request (a question, a deck, an image, a brand-new build) ArksAI moves itself to the right mode for it instead of forcing it through the current one. Built into the seamless flow: a vague ask → ArksAI asks a short round of clarifying questions first (never refuses, never blindly guesses); a coding ask → it **plans first** (shows exactly what it'll build) and waits for the user to approve (→ autonomous build) or revise.
- Plan approval gate — when ArksAI plans a build it presents the plan, then shows an explicit **"✓ Approve & build" / "Revise"** card (Approve kicks off the autonomous build; Revise drops focus into the message box). The gate is **structural**, not just a suggestion: building can only begin on your next turn after a plan — the agent cannot skip straight from planning to building in the same breath. Approve **reliably** starts the build: the plan must be complete (no trailing question) before it's offered, and on approval the agent is blocked from re-submitting the plan and goes straight to building (so Approve never loops back to the card).

## B2B department platform
- Department-aware studio — Marketing, Sales, Finance/Strategy, HR·People & Ops, Engineering, BI & Analytics, Tax & Compliance (UAE), Legal (UAE), plus **Personal** and **Learning** for everyday non-business use. Pick your function and ArksAI is **ready with that team's skills** (its persona/standards load on the session). Each task is an **example you tap to open a fresh chat already specialized for it** — no canned prompt is fired; the chat just waits for you, and your first message names it. Or type your own brief in the box.
- ~70-task catalog grouped **Create / Analyze / Operate**, each a ready-to-run brief in the right mode.
- Per-task expert standards (server-side) — a department persona (FP&A rigor, inclusive HR, RevOps, brand-growth, senior-eng, BI/analytics, UAE tax manager) + research-backed standards injected per task.
- **Developer tier for the Engineering team** — five deep developer expertises (canon harvested from the claude-skills library, reimplemented in TypeScript, zero new deps): **database schema design** (normalize → keys/indexes/relationships, Mermaid ERD + DDL + migration plan), **API design & review** (REST conventions, versioning, pagination, idempotency, error shapes, auth + a design scorecard), **API test suite** (happy-path + input-validation + the auth matrix + error codes + contract checks, then exercised), **code review** (correctness/security/readability/performance, severity-tagged with concrete fixes + blast-radius), and **dependency audit** backed by a new deterministic **`dependency_auditor`** tool — pure, offline, no key: parses package.json / requirements.txt and flags floating/unpinned ranges, duplicates, pre-1.0 pins, and a missing lockfile, honestly noting it can't see live CVEs offline (never fabricates one; recommends `npm audit` / `pip-audit`). Every developer deliverable is a **designed, typography-first document** (generate_doc / render_report), not a raw markdown/code dump.
- **Auto-selected expertise (zero-pick)** — you no longer have to pick a department to get expert standards: a free-form message ("make me a monthly budget", "write a job description", "draft an NDA", "build a cash-flow forecast") is read by a fast, deterministic trigger-based router that silently loads the right expertise (the exact task standard when it's confident, else the department persona). A picked play always wins; if nothing matches, it stays the general agent — so it's purely additive. (Off-switch: `EXPERTISE_AUTOROUTE=false`.)
- **Thoughtful when it's unsure (confidence → clarify)** — the auto-router now behaves like a careful expert instead of guessing. When it's confident it silently loads the exact task expertise; when the signal is softer it loads only the **department persona** (still the right expert voice, never a wrong specific); and when a message is genuinely too thin to know what you want ("make me something nice", "help with my thing tomorrow"), it asks **one warm, specific question** to narrow it — never a blind guess, never "I can't help with that". A clear request with a real subject still goes straight to building. A specific skill is **never** fired on a low-confidence match (the "never confidently wrong" guard). (Off-switch: `EXPERTISE_CLARIFY=false`.)
- **Personal / everyday expertise (ArksAI for everyone, not just business)** — two non-business lanes anyone can use without picking anything: a **Personal** department (my monthly/household budget — friendly, formula-driven; savings & debt-payoff plan; **"should I buy / sell" big-purchase valuation** that researches real cited listings and gives a buy + resale range — the "value my Porsche / iPhone" case; résumé/CV; cover letter; complaint/dispute letter; formal letter; email/message rewrite; trip itinerary; event/party plan; personal checklist) and a **Learning** department (explain a concept at your level; study guide / revision notes; faithfully summarize a document). Plain language, no jargon, real cited facts (never fabricated). A free-form message ("household budget for next month", "should I buy a 2019 Cayenne at 200k km", "explain compound interest to a 15-year-old", "write a complaint letter — the airline lost my bag") auto-routes to the right one.
- **Drift-proof expertise registry** — every expertise's `<dept>.<task>` key + department now lives in ONE source of truth (`shared/expertiseKeys.ts`) that both the client play catalog and the server standards derive from (the client play key is even compiler-typed against it). Cross-file **sync tests** fail the build the moment a key is half-added — a play with no standard/triggers, a standard/trigger with no play, a department with no persona, or two tasks sharing a trigger phrase — so adding a skill is a safe, consistent, template-driven act (recipe in `EXPERTISE_AUTHORING.md`). No behavior change: every existing play, standard, and trigger is unchanged.
- **Leaner prompts, same quality (progressive disclosure)** — the system prompt is now assembled from a slim always-on core plus on-demand slices (the music/image/document-tool notes, the report page-mechanics, the design system, the per-task expert standards), and a slice loads **only when the current task can use it**. A read-only planning turn no longer carries the build/generation tool notes it can't act on (~48% shorter), and the per-task expertise loads only for that task — so each turn costs fewer tokens with **no loss of capability**. The guarantee is hard-locked: a **report build receives every report rule byte-for-byte** as before (a test asserts the report and code prompts are identical with the feature on vs off), so the painstakingly-tuned report engine cannot regress. (Off-switch: `EXPERTISE_PROGRESSIVE=false` restores the full prompt instantly.)
- **Marketing makes finished creatives (image + crisp text + logo)** — a `generate_creative` capability produces a ready-to-post **PNG/JPEG**: it generates an on-brand, text-free AI background with reserved negative space, uses **M3 vision to pick the calmest zone + the text colour that reads there**, then composites the headline/subhead/**check-marked feature list**/CTA as **pixel-perfect type** (HTML/CSS, never the image model's garbled lettering) plus the **user's uploaded logo** (or a tasteful top-left "LOGO" placeholder) if provided, with a contrast scrim and a vision QC + auto-correct pass. It also **scrubs any copy the model put into the imagery prompt** (literal headline/CTA, quoted strings, "text that says…") so the background can't come back with garbled lettering, and re-generates with a hard no-text directive if text still leaks in. The dedicated **Ad & social creative** play, the email/social kit, and landing/event heroes all use it at channel sizes (1:1 / 4:5 / 9:16 / 16:9 / 1.91:1); graceful CSS/SVG fallback when unkeyed. The agent **asks for your logo first** (or uses a clean placeholder), and social creatives bake in **high-conversion tactics** (a benefit hook, one clear CTA, truthful proof/specifics, thumbnail-legible type) — kept **separate from email**, which is optimized for the inbox instead.

## Day-to-day capabilities
- Recurring/scheduled tasks — a durable server scheduler (daily/weekly/interval) that fires a fresh session even with the browser closed; managed via a Schedules dialog. Times are read in **your local timezone** (captured from your browser, DST-correct), so "daily 08:00" fires at 08:00 where you are — not on the server's clock.
- Data in — `fetch_data` pulls a public CSV/JSON/published-Sheet URL (SSRF-guarded).
- **Ad-platform connectors (Meta · Google Ads · TikTok)** — org admins connect their ad accounts under **Settings → Connections** (OAuth); the agent then pulls **live** performance via `fetch_ads` straight into dashboards and reports (spend/impressions/clicks/ctr/conversions, by campaign/ad/day). Per-org, OAuth tokens stored **encrypted** (AES-256-GCM) and never exposed to the model; auto-refreshed on expiry; each provider gates on its app credentials. ## Organizations (multi-tenant "spaces")
- **Isolated org spaces** — every session/project/deployment is scoped to an org; **everyone — members AND the platform operator — sees only their own workspace's data** (cross-org access → 404). The operator's **super-admin** role unlocks platform administration (provisioning orgs, reviewing the waitlist, managing any org's members), **not** a commingled view of other orgs' chats.
- **Roles**: super-admin (operator) → org **admin** → **member**; new sessions/projects are stamped with the creator's org.
- **Project-level visibility** — each project is org-wide by default, or **private to its creator + invited members** (enforced in every list/get query; cross-visibility access → 404). The owner or an admin manages sharing.
- **Invite-only, link-based onboarding** (no email infra): the super-admin creates an org + invites its admin; org admins invite their team — each invite is a one-time link to copy/share. Opening it sets a password and logs the member straight in; memberships revoke instantly (killing live sessions). Being **granted access removes that person from the waitlist** automatically (on invite issue and on accept), so the operator's review list only shows people not yet actioned.
- **In-app admin panel**: create orgs, **delete an org and ALL its data** (operator-only, cascades sessions/projects/published apps/schedules/commands/profile/analytics + removes member accounts orphaned by the deletion; the Default workspace is protected), review the waitlist (leads), manage members + invite links; team-member email login (the platform operator signs in separately at the unlinked `/operator`) and an `/invite/<token>` accept page. The invite field is a prominent full-width email; **free/personal email domains are blocked** (server-authoritative, gmail/outlook/…) and an invite whose domain differs from the admin's own is **flagged as out-of-org** (confirm to proceed). A company's workspace is its OWN and is **not swappable** — there is no workspace switcher in the UI for anyone (the sidebar just names the current workspace).
- **Cross-org isolation, audited & hardened** — every user-facing resource is scoped to the authenticated org (never a client-supplied id): sessions + all `/api/sessions/:id/*`, projects (+ creator/invited visibility), **the live sidebar event stream** (a tenant only receives its own org's session status/titles), **deployments** (list + stop/restart/delete — a slug from another org → 404), **schedules** (list/create/enable/delete, and a fired run lands in the owning org), **custom commands** (per-org keyed `(org_id, name)` so orgs never see/overwrite each other's), and org **memory**. Mutating a project (edit/delete/upload) additionally requires being its owner or an org admin. Backed by isolation tests **including an HTTP-level red-team** that signs in as one org and confirms it cannot reach another org's data on any route (list, by-id, sub-routes, or destructive writes) — and a check that the **operator** is confined to its own workspace (it opens its own chats but gets a 404 on another org's session/events/projects/schedules/deployments) while keeping the admin provisioning surface.
- Shipped **non-breaking**: the existing operator login keeps its platform-admin powers via the super-admin role (now scoped to its own workspace for data reads, like every tenant), and all prior data lives in a bootstrapped "Default" org.
- **Per-org shared brain + an onboarding designed to be FINISHED** — a new org admin gets a fully-visible, agent-led first run built on how anticipation works (dopamine = a seeking signal driven by a reward that beats expectation): a vivid promise + one tiny ask opens a loop they want to close, an **endowed 3-step tracker** (Brand → Profile → First build) shows them already moving, and a **live brand-reveal panel** beside the chat lights up with their real accent, palette and "about" the moment ArksAI reads their site or logo — the studio visibly becomes theirs. ArksAI **crawls the org's website** **or reads an uploaded logo's colours** (`extract_palette`, deterministic — and vision works in every mode, so it never claims it can't see the image), saves the brand early so the panel pops, asks a couple of quick questions, then `save_org_profile` (complete) and tees up an exciting first build. That brand + "about" + a recalled digest of the org's own past chats are injected into **every** session in the org (brand applied consistently unless the user overrides). Members joining later inherit it silently; the admin can re-run/skip/edit.
- **Strict per-org memory isolation** — org memory lives under an `org:<id>` scope derived only from the authenticated identity (never client input). A tenant org reads/writes **only its own** scope — never the deployment-`global` notes, never another org — enforced in the runner's context builder *and* the memory API (read/write/delete), with repo memory namespaced per org. Cross-org isolation is unit-tested.

## Analytics & insight (admin)
- **Operator analytics console** (super-admin, full-screen from the sidebar) — a **dense, editorial "data desk"** (tabular figures, hairline rules, **week-over-week delta chips + inline sparklines** on every headline metric for fast reading) to understand how the whole platform is used at a glance: headline KPIs (active users 7d/30d, **stickiness = DAU/MAU**, sessions, success rate, **time-to-first-build**, cost, orgs/users, live apps, waitlist), active-users/sessions/cost-per-day trends, the **acquisition funnel** (lead → signup → onboarded → built → published), **feature adoption** by play, splits by mode and model, quality (done vs error), cost by model, a **signup-cohort retention** grid, and named **per-org and per-user drill-down** tables.
- **Per-user drill-down** — click any user (operator) or member (org admin) to open a metadata-only detail panel: their sessions, success rate, cost, time-to-first-build, a 30-day activity chart, what they build (plays/modes/models), and their orgs — scoped to the viewer's permissions.
- **Activation: time-to-first-build** — median time from signup to a user's first build, surfaced as a KPI and per-user, so onboarding friction is visible.
- **Actionable alerts (no setup)** — derived from existing metrics with no thresholds to configure: **cost-spike** detection (an org's last-7-days spend vs its trailing weekly baseline) and **churn-risk** orgs (onboarded + once-active but gone quiet) for the operator; per-org admins see their own cost-spike + inactive members. Quiet by default — shows "all clear" when nothing's wrong.
- **Scheduled digests** — a periodic platform snapshot (every `ANALYTICS_DIGEST_HOURS`, default daily) is computed and stored for the operator to review in-app (with deltas vs the previous one), and pushed to a webhook if `ANALYTICS_DIGEST_WEBHOOK` (Slack/Zapier/…) is configured.
- **CSV export** — one-click download of the orgs, users, and per-org members tables (client-side, no round-trip).
- **Per-org dashboards** — an org admin (or the operator drilling in) gets the focused subset inside the admin panel's **Usage & engagement** tab: engagement KPIs, active-members/sessions trends, the activation funnel, what the team builds (plays/modes/models), retention cohorts, alerts, and a clickable per-member activity table — scoped strictly to that org.
- **Lightweight event-tracking layer** — a non-blocking `track()` writes usage events (`app_open`, `run_finished`, …) to an `analytics_events` table with a precomputed epoch-day bucket (zero date-SQL, SQLite+Postgres portable); metrics also derive from existing tables so they work from day one and get richer as events accrue.
- **Privacy is absolute — metadata only.** Analytics read only counts, timestamps, status, mode/model, the play key, tokens and cost; they **never** touch the `timeline` table or any message/document content. Enforced at both boundaries (a write-side scalar-only `props` allowlist + a grep-able test that the analytics modules contain no content reads) and gated end-to-end: operator routes are super-admin-only, per-org routes require that org's admin (a per-user drill is membership-gated so an admin can't probe non-members) — covered by an HTTP red-team test (a non-operator gets 403 on platform analytics; an org admin cannot read another org's).
